# Писарь

Локальное десктопное приложение для распознавания речи с разделением по
спикерам и таймкодами по смысловым кускам — фразам и репликам, а не
фиксированным интервалам.

![Platform](https://img.shields.io/badge/platform-Windows-0078D6)
![Python](https://img.shields.io/badge/python-3.10--3.12-3776AB)
![GPU](https://img.shields.io/badge/GPU-NVIDIA%20CUDA%20(опционально)-76B900)
![UI](https://img.shields.io/badge/UI-PySide6-41CD52)

Whisper даёт текст, pyannote.audio — кто когда говорил, faster-whisper
(CTranslate2) всё это считает, а Писарь собирает результат в удобный вид.
Работает локально, на GPU или CPU, без отправки аудио куда-либо, кроме
одноразовой загрузки моделей с Hugging Face.

## Возможности

- Распознавание речи через `faster-whisper` (модели tiny … large-v3)
- Разделение по спикерам через `pyannote.audio`, число спикеров — авто,
  точное или диапазон
- Таймкоды по смысловым кускам: разбивка идёт по паузам, смене спикера и
  границам предложений, а не по произвольным интервалам
- Очередь из нескольких файлов — обрабатываются по очереди в фоне
- Переименование «Спикер 1 / Спикер 2» в реальные имена после распознавания
- Экспорт в TXT, SRT, JSON, DOCX
- Работает на GPU (CUDA) или CPU

## Быстрый старт

```bash
setup.bat   # создаёт venv, ставит зависимости, спрашивает про GPU
run.bat     # запускает приложение
```

Нужно заранее: Python 3.10–3.12 (**не** из Anaconda/Miniconda — см.
[Диагностика](#диагностика-и-известные-проблемы)) и `ffmpeg` в `PATH`.

Для диаризации по спикерам ещё нужен бесплатный токен Hugging Face — см.
[раздел ниже](#токен-hugging-face-для-диаризации). Без него приложение тоже
работает — просто выключите галочку «Включить диаризацию» и получите чистую
транскрипцию без разделения на голоса.

## Установка вручную

<details>
<summary>Если <code>setup.bat</code> отругался, или нужен полный контроль</summary>

### 1. Виртуальное окружение и зависимости

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 2. PyTorch с поддержкой CUDA — ставить последним

`requirements.txt` намеренно не содержит `torch`: если поставить его раньше
остальных пакетов, `pyannote.audio` при установке молча заменит нужную
CUDA-сборку на CPU-сборку с PyPI, и torch перестанет импортироваться
(`OSError: ... c10.dll`).

```bash
pip install --force-reinstall --no-deps torch torchaudio --index-url https://download.pytorch.org/whl/cu124
```

Без GPU — то же самое, но без `--index-url` (обычная CPU-сборка). Проверка:

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

Ожидается версия с суффиксом `+cu...` и `True`, если есть GPU.

### 3. ffmpeg

`ffmpeg`/`ffprobe` должны быть в `PATH` — используются для конвертации
любого аудио/видео файла в WAV. Проверка: `ffmpeg -version`.

</details>

## Токен Hugging Face (для диаризации)

Модель `pyannote/speaker-diarization-3.1` распространяется через Hugging
Face и требует принятия лицензии на **всех** репозиториях, которые она
использует внутри себя:

1. Токен (тип **Read**): https://huggingface.co/settings/tokens
2. Примите условия на каждой из страниц (кнопка *Agree and access repository*):
   - https://huggingface.co/pyannote/speaker-diarization-3.1
   - https://huggingface.co/pyannote/segmentation-3.0
   - https://huggingface.co/pyannote/speaker-diarization-community-1
3. Вставьте токен в поле «Hugging Face токен» в приложении — сохранится
   локально в `~/.whisper_diarizer/config.json`.

Если после этого всё равно 403 — запустите `check_hf_access.py` с вашим
токеном, он покажет, какому аккаунту токен принадлежит и какая именно
модель заблокирована:

```bash
.venv\Scripts\python.exe check_hf_access.py hf_ваш_токен
```

## Использование

1. **«Добавить файлы...»** — можно выбрать сразу несколько аудио/видео
   файлов (mp3, wav, m4a, mp4, mkv, ...), они встают в очередь.
2. Настройте модель Whisper, язык, устройство (auto/cuda/cpu), диаризацию и
   число спикеров — общие настройки для всей очереди.
3. **«Запустить очередь»** — файлы обрабатываются по одному, прогресс и лог
   видны внизу. «Остановить после текущего файла» прерывает очередь.
4. Клик по обработанному файлу в очереди показывает его результат — текст с
   таймкодами и цветными метками спикеров.
5. **«Переименовать спикеров»** под результатом — впишите реальные имена
   вместо «Спикер 1/2/...» и нажмите «Применить имена».
6. Экспорт (TXT/SRT/JSON/DOCX) — для открытого сейчас файла, имя файла по
   умолчанию берётся из названия исходника.

## Как формируются таймкоды

Whisper даёт слова с таймстампами и сегменты по паузам (VAD). Каждому слову
назначается спикер по максимальному перекрытию с интервалами диаризации
pyannote. Соседние слова объединяются в один смысловой кусок, пока:

- не сменился спикер,
- не случилась пауза длиннее ~1 секунды,
- фрагмент не стал слишком длинным (тогда режем по концу предложения).

Таймкод ставится на фразу/реплику целиком, а не на произвольный интервал
времени.

## Модели Whisper

| Модель | Скорость | Точность | Когда использовать |
|---|---|---|---|
| `tiny` / `base` / `small` | быстро | ниже | черновая расшифровка, слабое железо |
| `medium` | средне | хорошая | компромисс без мощной GPU |
| `large-v3` | медленно | лучшая | основной вариант при наличии GPU |
| `distil-large-v3` | быстро | почти как large | лучший баланс для GPU |

## Структура проекта

```
app/
  config.py             — сохранение настроек пользователя
  audio_utils.py         — конвертация в WAV через ffmpeg
  transcribe.py           — обёртка над faster-whisper
  diarize.py              — обёртка над pyannote.audio
  worker_transcribe.py    — распознавание в отдельном процессе
  worker_diarize.py       — диаризация в отдельном процессе
  merge.py                — сборка смысловых кусков со спикерами
  export.py               — экспорт в TXT/SRT/JSON/DOCX
  pipeline.py              — оркестрация пайплайна для одного файла
  gui.py                    — окно PySide6 (очередь, настройки, результат)
main.py             — точка входа
setup.bat           — установка venv и зависимостей одной командой
run.bat             — запуск приложения
check_hf_access.py  — диагностика доступа токена к моделям pyannote на HF
```

Транскрипция (`ctranslate2`) и диаризация (`torch`/`pyannote`) намеренно
запускаются в отдельных процессах — при совместном использовании GPU в
одном процессе они конфликтуют из-за разных версий cuDNN, которые каждая
библиотека тащит с собой, и приложение падает без исключения (нативный
краш). `pipeline.py` управляет обоими процессами через `worker_*.py` и
временные JSON-файлы.

## Диагностика и известные проблемы

<details>
<summary><code>DLL load failed while importing QtCore</code> или тихий
segmentation fault</summary>

Причина почти всегда одна: `.venv` создан от Python из Anaconda/Miniconda.
В процессе оказываются старые DLL из папки `anaconda3\` (например,
`msvcp140.dll` пятилетней давности), и PySide6/ctranslate2 падают при
попытке их использовать. Решение — создать `.venv` от «обычного» Python
(python.org или Microsoft Store), не от Anaconda.
</details>

<details>
<summary>Приложение падает без сообщения об ошибке во время диаризации</summary>

`ctranslate2` (Whisper) и `torch` (диаризация) каждый несут свою версию
cuDNN. При одновременной работе с GPU в одном процессе это приводит к
нативному краху. В этом проекте уже решено — транскрипция и диаризация
выполняются в отдельных процессах (`worker_transcribe.py` /
`worker_diarize.py`).
</details>

<details>
<summary><code>torchcodec is not available</code></summary>

Новые версии `pyannote.audio` по умолчанию читают аудио через `torchcodec`,
который капризно ставится на Windows. Приложение обходит это — грузит WAV
через `soundfile` и передаёт готовый тензор напрямую, без `torchcodec`.
</details>

<details>
<summary><code>403 Gated repo</code> при загрузке модели диаризации</summary>

Не принята лицензия хотя бы на одной из трёх моделей pyannote (см.
[Токен Hugging Face](#токен-hugging-face-для-диаризации)), либо токен и
аккаунт, где принята лицензия, не совпадают. Проверьте `check_hf_access.py`.
</details>
