# Писарь

Локальное десктопное приложение для распознавания речи с разделением по
спикерам и таймкодами по смысловым кускам — фразам и репликам, а не
фиксированным интервалам.

![Platform](https://img.shields.io/badge/platform-Windows-0078D6)
![Python](https://img.shields.io/badge/python-3.10--3.12-3776AB)
![GPU](https://img.shields.io/badge/GPU-NVIDIA%20CUDA%20(опционально)-76B900)
![UI](https://img.shields.io/badge/UI-PySide6-41CD52)

Whisper даёт текст, pyannote.audio — кто когда говорил, faster-whisper
(CTranslate2) всё это считает, а Писарь собирает результат в удобный вид.
Работает локально, на GPU или CPU, без отправки аудио куда-либо, кроме
одноразовой загрузки моделей с Hugging Face.

## Возможности

- Распознавание речи через `faster-whisper` (модели tiny … large-v3)
- Разделение по спикерам через `pyannote.audio`, число спикеров — авто,
  точное или диапазон
- Таймкоды по смысловым кускам: разбивка идёт по паузам, смене спикера и
  границам предложений, а не по произвольным интервалам
- Очередь из нескольких файлов — обрабатываются по очереди в фоне
- Переименование «Спикер 1 / Спикер 2» в реальные имена после распознавания
- Экспорт в TXT, SRT, JSON, DOCX
- Работает на GPU (CUDA) или CPU

## Быстрый старт

```bash
setup.bat   # создаёт venv, ставит зависимости, спрашивает про GPU
run.bat     # запускает приложение
```

Нужно заранее: 64-битный Python **3.10, 3.11 или 3.12** (**не** из
Anaconda/Miniconda — см. [Диагностика](#диагностика-и-известные-проблемы)) и
`ffmpeg` в `PATH` (`winget install Gyan.FFmpeg`).

`setup.bat` сам находит подходящий Python через `py`-лаунчер, даже если в
системе их несколько (например, 3.13 по умолчанию рядом с 3.12), пересоздаёт
`.venv`, если он собран не той версией, и пишет подробный журнал в
`setup.log`. Если что-то пошло не так — покажет хвост журнала; этот файл
можно прислать разработчику.

Для диаризации по спикерам ещё нужен бесплатный токен Hugging Face — см.
[раздел ниже](#токен-hugging-face-для-диаризации). Без него приложение тоже
работает — просто выключите галочку «Включить диаризацию» и получите чистую
транскрипцию без разделения на голоса.

## Установка вручную

<details>
<summary>Если <code>setup.bat</code> отругался, или нужен полный контроль</summary>

### 1. Виртуальное окружение и зависимости

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 2. PyTorch с поддержкой CUDA (только если есть видеокарта NVIDIA)

Шаг 1 уже поставил `torch==2.8.0` с PyPI — это CPU-сборка, для неё больше
ничего делать не нужно. Для видеокарты NVIDIA замените её на CUDA-сборку
**той же версии**:

```bash
pip install --force-reinstall --no-deps torch==2.8.0 torchaudio==2.8.0 --index-url https://download.pytorch.org/whl/cu126
```

`--no-deps` обязателен — иначе pip заново разрешит зависимости и может
вернуть CPU-сборку. Версия `2.8.0` зафиксирована в `requirements.txt`
намеренно: ровно её ждёт `pyannote.audio` 4.x, и на ней все ограничения
зависимостей (`sympy`, `lightning`, …) совместимы между собой. Повторный
`pip install -r requirements.txt` CUDA-сборку не затирает — `2.8.0+cu126`
удовлетворяет `torch==2.8.0`.

Проверка:

```bash
python -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

Ожидается `2.8.0+cu126 True` с видеокартой и `2.8.0+cpu False` без неё.

### 3. ffmpeg

`ffmpeg`/`ffprobe` должны быть в `PATH` — используются для конвертации
любого аудио/видео файла в WAV. Проверка: `ffmpeg -version`.

</details>

## Токен Hugging Face (для диаризации)

Модель `pyannote/speaker-diarization-3.1` распространяется через Hugging
Face и требует принятия лицензии на **всех** репозиториях, которые она
использует внутри себя:

1. Токен (тип **Read**): https://huggingface.co/settings/tokens
2. Примите условия на каждой из страниц (кнопка *Agree and access repository*):
   - https://huggingface.co/pyannote/speaker-diarization-3.1
   - https://huggingface.co/pyannote/segmentation-3.0
   - https://huggingface.co/pyannote/speaker-diarization-community-1
3. Вставьте токен в поле «Hugging Face токен» в приложении — сохранится
   локально в `~/.whisper_diarizer/config.json`.

Если после этого всё равно 403 — запустите `check_hf_access.py` с вашим
токеном, он покажет, какому аккаунту токен принадлежит и какая именно
модель заблокирована:

```bash
.venv\Scripts\python.exe check_hf_access.py hf_ваш_токен
```

## Использование

1. **«Добавить файлы...»** — можно выбрать сразу несколько аудио/видео
   файлов (mp3, wav, m4a, mp4, mkv, ...), они встают в очередь.
2. Настройте модель Whisper, язык, устройство (auto/cuda/cpu), диаризацию и
   число спикеров — общие настройки для всей очереди.
3. **«Запустить очередь»** — файлы обрабатываются по одному, прогресс и лог
   видны внизу. «Остановить после текущего файла» прерывает очередь.
4. Клик по обработанному файлу в очереди показывает его результат — текст с
   таймкодами и цветными метками спикеров.
5. **«Переименовать спикеров»** под результатом — впишите реальные имена
   вместо «Спикер 1/2/...» и нажмите «Применить имена».
6. Экспорт — для открытого сейчас файла, имя файла по умолчанию берётся из
   названия исходника. Форматы для Premiere Pro — в разделе ниже.

## Экспорт в Premiere Pro

| Кнопка | Файл | Что это |
|---|---|---|
| **Субтитры SRT (Premiere)** | `имя.srt` | Экранные субтитры: короткие реплики, до двух строк по ~42 символа, до 6 секунд. Реплики режутся по предложениям и запятым, а не через каждые N секунд. |
| **Транскрипт Premiere (JSON)** | `имя_premiere.json` | Транскрипт с таймкодом на **каждое слово** и именами спикеров — для панели Text и текстового монтажа. |
| SRT: реплики | `имя_transcript.srt` | Одна запись на реплику целиком с именем спикера — чтобы читать расшифровку на таймлайне. Для субтитров в кадре не подходит: реплики бывают по 30 секунд. |

Галочка «Писать имена спикеров в субтитрах» добавляет «Имя: » перед первой
репликой каждого выступающего.

**Субтитры (SRT).** File → Import, затем перетащите `.srt` на таймлайн — либо
Text → Captions → Import captions from file (в вашей версии пункт может
называться чуть иначе). Файл пишется как UTF‑8 **с BOM** и переводами строк
CRLF: по отзывам пользователей, Premiere читает UTF‑8 без BOM неправильно
(кириллица превращается в мусор) и ждёт CRLF даже на Mac. Другие программы
(DaVinci Resolve, VLC, ffmpeg) BOM спокойно принимают.

**Транскрипт (JSON).** Откройте клип в Source Monitor → панель Text →
вкладка Transcript → меню «⋯» → Import → **Import Static Transcript** и
выберите файл. Premiere построит транскрипт, синхронизированный со звуком:
клик по слову переходит к нему, работают поиск и монтаж правкой текста —
в том числе для языков, которые Premiere сам расшифровывать не умеет. Имена
спикеров берутся из окна «Переименовать спикеров», язык — тот, на котором
распознан файл. Функция появилась в Premiere Pro в 2025 году, нужна свежая
версия.

> **Что не поддерживается: `.prtranscript`.** Это бинарный файл (FlatBuffers),
> который Premiere создаёт сам при «Export transcript»; Adobe его формат не
> публиковала. Импортировать в Premiere можно JSON — он несёт те же данные
> (слова с таймингами, спикеры, язык). Писать `.prtranscript` вслепую было бы
> обманом: файл «выглядел бы правильно», но Premiere мог бы отказаться его
> открыть. Если у вас есть такой файл из вашего Premiere — пришлите, тогда
> можно разобрать формат по образцу и проверить.
>
> Структура JSON собрана по опубликованным образцам формата импорта Adobe
> (сама спецификация лежит вложением на форуме Adobe и недоступна для
> автоматической загрузки), формат проверен на соответствие образцу и на
> случайных данных, но **импорт в живой Premiere автором не проверялся** —
> если в вашей версии что-то не подхватится, сообщите.

## Как формируются таймкоды

Whisper даёт слова с таймстампами и сегменты по паузам (VAD). Каждому слову
назначается спикер по максимальному перекрытию с интервалами диаризации
pyannote. Соседние слова объединяются в один смысловой кусок, пока:

- не сменился спикер,
- не случилась пауза длиннее ~1 секунды,
- фрагмент не стал слишком длинным (тогда режем по концу предложения).

Таймкод ставится на фразу/реплику целиком, а не на произвольный интервал
времени.

## Модели Whisper

| Модель | Скорость | Точность | Когда использовать |
|---|---|---|---|
| `tiny` / `base` / `small` | быстро | ниже | черновая расшифровка, слабое железо |
| `medium` | средне | хорошая | компромисс без мощной GPU |
| `large-v2` / `large-v3` | медленно | лучшая | основной вариант при наличии GPU |

Для русской речи ставьте язык «Русский» явно, а не «Автоопределение» — так
модель не тратит первые секунды на угадывание и реже путает слова. Если
`large-v3` на конкретной записи ошибается, попробуйте `large-v2`, и наоборот:
на разной речи лучше срабатывает то одна, то другая.

Размер моделей: `large` — около 3 ГБ, скачивается один раз при первом запуске
(в окне видно процент и объём загрузки).

> Английская `distil-large-v3` намеренно убрана из списка: она обучена только
> на английском, и на русском вместо ускорения даёт бессмыслицу.

## Структура проекта

```
app/
  config.py             — сохранение настроек пользователя
  audio_utils.py         — конвертация в WAV через ffmpeg
  hub_utils.py            — надёжная загрузка моделей: кэш, повторы, прогресс
  transcribe.py           — обёртка над faster-whisper
  diarize.py              — обёртка над pyannote.audio
  worker_transcribe.py    — распознавание в отдельном процессе
  worker_diarize.py       — диаризация в отдельном процессе
  merge.py                — сборка смысловых кусков со спикерами
  export.py               — экспорт в TXT/SRT/JSON/DOCX
  subtitles.py            — нарезка реплик на экранные субтитры (2 строки × 42 символа)
  premiere.py             — транскрипт Premiere Pro (JSON, «Import Static Transcript»)
  pipeline.py              — оркестрация пайплайна для одного файла
  gui.py                    — окно PySide6 (очередь, настройки, результат)
main.py             — точка входа
setup.bat           — установка venv и зависимостей одной командой
run.bat             — запуск приложения
check_hf_access.py  — диагностика доступа токена к моделям pyannote на HF
```

Транскрипция (`ctranslate2`) и диаризация (`torch`/`pyannote`) намеренно
запускаются в отдельных процессах — при совместном использовании GPU в
одном процессе они конфликтуют из-за разных версий cuDNN, которые каждая
библиотека тащит с собой, и приложение падает без исключения (нативный
краш). `pipeline.py` управляет обоими процессами через `worker_*.py` и
временные JSON-файлы.

## Диагностика и известные проблемы

<details>
<summary><code>DLL load failed while importing QtCore</code> или тихий
segmentation fault</summary>

Причина почти всегда одна: `.venv` создан от Python из Anaconda/Miniconda.
В процессе оказываются старые DLL из папки `anaconda3\` (например,
`msvcp140.dll` пятилетней давности), и PySide6/ctranslate2 падают при
попытке их использовать. Решение — создать `.venv` от «обычного» Python
(python.org или Microsoft Store), не от Anaconda.
</details>

<details>
<summary>Приложение падает без сообщения об ошибке во время диаризации</summary>

`ctranslate2` (Whisper) и `torch` (диаризация) каждый несут свою версию
cuDNN. При одновременной работе с GPU в одном процессе это приводит к
нативному краху. В этом проекте уже решено — транскрипция и диаризация
выполняются в отдельных процессах (`worker_transcribe.py` /
`worker_diarize.py`).
</details>

<details>
<summary><code>torchcodec is not available</code></summary>

Новые версии `pyannote.audio` по умолчанию читают аудио через `torchcodec`,
который капризно ставится на Windows. Приложение обходит это — грузит WAV
через `soundfile` и передаёт готовый тензор напрямую, без `torchcodec`.
</details>

<details>
<summary><code>403 Gated repo</code> при загрузке модели диаризации</summary>

Не принята лицензия хотя бы на одной из трёх моделей pyannote (см.
[Токен Hugging Face](#токен-hugging-face-для-диаризации)), либо токен и
аккаунт, где принята лицензия, не совпадают. Проверьте `check_hf_access.py`.
</details>

<details>
<summary><code>Library cublas64_12.dll is not found or cannot be loaded</code></summary>

`ctranslate2` (движок Whisper) приносит с собой cuDNN, но не cuBLAS. Приложение
берёт cuBLAS из установленного PyTorch с CUDA — поэтому CUDA Toolkit ставить
не нужно, **но нужна CUDA-сборка torch** (`2.8.0+cu126`, а не `2.8.0+cpu`):
проверьте `python -c "import torch; print(torch.__version__)"` и при
необходимости выполните шаг 2 из «Установки вручную».

Если библиотек всё равно нет, приложение само переключается на CPU и пишет
об этом в статусе (медленнее, но работает). Тогда для GPU-ускорения помогает
установка [CUDA Toolkit 12.x](https://developer.nvidia.com/cuda-downloads).
</details>

<details>
<summary><code>Pipeline.from_pretrained() got an unexpected keyword argument</code>
или <code>hf_hub_download() got an unexpected keyword argument</code></summary>

Несовместимые версии `pyannote.audio` и `huggingface_hub` — старый
`pyannote.audio` (&lt;4.0) дёргает устаревший `use_auth_token`, а новый
`huggingface_hub` его уже не принимает. Обновите пакет:
`pip install --upgrade "pyannote.audio>=4.0.0"`.
</details>

<details>
<summary>Долго «висит» на 6%, или ошибка <code>Server disconnected without sending a response</code></summary>

Это загрузка модели с huggingface.co: при первом запуске `large` — около
3 ГБ. В окне показывается процент и объём; если процента нет — идёт
проверка соединения.

При обрыве связи (нестабильный интернет, VPN/прокси, антивирус, блокировки)
приложение само повторяет попытку до 5 раз (2, 5, 10, 20 секунд паузы) и
пишет об этом в статусе. Если все попытки неудачны — покажет понятное
сообщение; просто запустите обработку заново: уже скачанные части не
пропадают, загрузка продолжается. Модель, скачанная один раз, дальше берётся
из кэша (`~/.cache/huggingface`) и работает **без интернета** — обрыв связи на
этом этапе больше не может сорвать обработку.
</details>

<details>
<summary><code>setup.bat</code> не находит Python или собирает окружение не той версией</summary>

Проверенные версии — 64-битные Python 3.10, 3.11, 3.12. Скрипт ищет их через
`py -3.12` / `-3.11` / `-3.10`, поэтому лишние Python в системе не мешают.
Если ни одного нет — установите Python 3.12 с python.org, отметив
«Add python.exe to PATH» и «py launcher». Подробности любой неудачи — в
`setup.log` рядом со скриптом.
</details>
